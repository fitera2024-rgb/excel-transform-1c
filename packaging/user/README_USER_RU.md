# Excel → OPIU Light — пользовательский пакет ФИТЭРА

## 1. Назначение

Сервис локально выполняет полный безопасный цикл:

`Excel → определение фактического формата → восстановление рабочей копии → проверка → преобразование → максимально полный preview → исправления → экспорт OPIU Light`.

В этой версии **нет ADO, записи в 1С, ODBC и live write**. Исходный Excel не изменяется.

## 2. Требования

- Windows 10/11 x64;
- Python 3.11 x64;
- один свободный порт из `8000`, `8765`, `8001`, `8010`, `8080`.

Интернет для установки библиотек не требуется: все wheel-файлы находятся внутри ZIP.

## 3. Запуск и остановка

1. Полностью распакуйте ZIP в новую папку. Не запускайте `.cmd` из окна просмотра ZIP.
2. Запустите `START_SERVICE.cmd`.
3. Пакет остановит предыдущий экземпляр именно Excel → OPIU Light на известных портах, не затрагивая чужие приложения.
4. При первом запуске будет создана `.venv`; затем откроется браузер.
5. Сервис продолжит работать в фоне после закрытия стартового окна.
6. Для остановки используйте `STOP_SERVICE.cmd`.

Фактический адрес сохраняется в `runtime\service.url`. Журналы находятся в `startup.log`, `runtime\service.stdout.log` и `runtime\service.stderr.log`.

## 4. Базовые справочники уже внутри пакета

После чистого запуска доступны:

- ERP-статьи — `271`;
- организации и узлы 1С — `357`;
- сценарии — `12`;
- ЦФО Инталев — `16`.

Загружать эти четыре файла для первого запуска не требуется.

Кнопка **«Загрузить / дополнить»** остаётся доступной. Первый явный импорт заменяет соответствующий встроенный каталог проверенными пользовательскими данными, последующие импорты добавляют или обновляют записи только по точному устойчивому ключу. Похожие названия автоматически не объединяются. Каталоги и подтверждённые соответствия сохраняются в `runtime\local.db` и доступны после перезапуска.

## 5. Поддерживаемые Excel-файлы

Сервис определяет формат по содержимому, а не по расширению файла. Поддерживаются:

- обычные `.xlsx` и `.xlsm`;
- защищённые OOXML-книги в OLE-контейнере;
- старые бинарные `.xls`/BIFF, в том числе ошибочно названные `.xlsx`;
- SpreadsheetML XML;
- восстанавливаемые OOXML-книги с некорректным регистром внутренних частей, внешними связями или узкими XML-повреждениями.

Для обработки создаётся отдельная рабочая `.xlsx`-копия внутри локального RUN. Оригинал сохраняется byte-for-byte. Если восстановление неоднозначно или небезопасно, сервис закрывает обработку понятным сообщением вместо пустого preview.

Формулы читаются по сохранённым в книге Excel-значениям. Макросы, рисунки и сложное оформление старого `.xls` не переносятся в рабочую копию, поскольку для преобразования используются бизнес-значения таблицы.

## 6. Обработка файла

1. Выберите верхнюю ветку и конкретную организацию/узел 1С.
2. Выберите сценарий, год и `Весь год` либо нужные месяцы.
3. Выберите исходный Excel.
4. Для защищённой книги введите пароль в поле формы. Пароль используется только в текущем запросе и не сохраняется.
5. Нажмите **«Построить preview»**.
6. При наличии нескольких структурно подходящих диапазонов выберите нужный по листу и строкам.

Для большого файла показывается сообщение: `Файл загружается и анализируется; не закрывайте страницу`.

Сервис поддерживает как подготовленные бюджетные книги АЮ/ПВ, так и годовой отчёт Инталев ОПИУ. Для годового Инталев ОПИУ он структурно определяет 12 месяцев, иерархию статей и исходный ЦФО, затем формирует строки OPIU Light.

## 7. ERP-сопоставления

ERP-код выбирается по иерархии:

`Тип расходов → Группа расходов → Статья → ERP-код`.

Для массового действия:

1. проверьте `Будет подтверждено: N строк`;
2. поставьте `Подтверждаю все заполненные ERP-сопоставления`;
3. нажмите `Применить все заполненные`.

Уже подтверждённые строки показываются статусом и повторно не входят в счётчик. Другие причины строки сохраняются.

## 8. Налогообложение не требуется

Для строки с неопределённым налогом можно выбрать `Налогообложение неважно`. Сервис покажет `Налогообложение: не требуется`, не подставляя НДС или другой режим.

Для всех подходящих строк используйте отдельную галку `Подтверждаю для всех строк: налогообложение неважно` и кнопку `Применить всё`. Счётчик показывает исходные строки, а не месяцы.

## 9. Сопоставление ЦФО Инталев

В верхнем блоке preview каждый уникальный ЦФО Инталев имеет:

- точный код, наименование и путь;
- число исходных строк;
- иерархический выбор конкретного узла 1С.

Можно подтвердить одно соответствие либо заполнить несколько, поставить `Подтверждаю все заполненные сопоставления ЦФО` и нажать `Применить всё`. Одно соответствие обновляет все связанные строки и месяцы. Mapping сохраняется локально и применяется после перезапуска.

Сервис не использует fuzzy-сопоставление и не объединяет разные ЦФО только по похожему названию.

## 10. Экспорт

Нажмите **«Экспортировать OPIU Light»**. Итоговый `.xlsx` содержит три листа в фиксированном порядке:

1. `OPIU Light` — прежний полный формат из 19 колонок; он сохранён без изменения для обратной совместимости.
2. `ОПИУ` — ADO-ориентированный формат из 17 колонок: организация, сценарий, период, организационные единицы, ЦФО, статья и сумма.
3. `Показатели` — ADO-структура из 8 колонок. Пока в текущем входном потоке нет источника каналов сбыта и показателей, лист создаётся с заголовками без выдуманных строк.

На листе `ОПИУ`:

- бизнес-строки сохраняются даже при отсутствии дополнительных справочных кодов;
- коды организационных единиц, ЦФО, номенклатуры и регионов остаются пустыми до загрузки соответствующих справочников;
- ERP-код статьи сохраняется текстом, включая начальные нули;
- сумма остаётся числом;
- период формируется как `01.2026`, `02.2026` и далее.

Старый лист `OPIU Light` по-прежнему содержит:

- все сформированные месяцы;
- нулевые и отрицательные суммы без изменения знака;
- подтверждённые ERP-коды и ЦФО;
- налоговый статус `Не требуется`;
- статусы `Требует внимания` и `Пропущено`;
- номер исходной строки.

Экспорт создаётся даже при наличии нерешённых бизнес-вопросов, чтобы пользователь видел максимально полный результат.

## 11. Обновление пакета

1. Остановите старую версию через `STOP_SERVICE.cmd`.
2. Распакуйте новый ZIP в новую папку.
3. Для сохранения пользовательских дополнений и mappings скопируйте старую папку `runtime` в новую версию.
4. Старую `.venv` не копируйте.

Без переноса `runtime` новый пакет начнёт с встроенных базовых справочников `271 / 357 / 12 / 16`.

## 12. Диагностика

- Python не найден: установите Python 3.11 x64 и Python Launcher/Add to PATH;
- `ERR_CONNECTION_REFUSED`: снова запустите `START_SERVICE.cmd` и откройте адрес из `runtime\service.url`;
- неверный пароль: выберите исходный файл повторно и проверьте пароль;
- старый/повреждённый файл не восстановлен: выберите другой файл либо передайте `startup.log` и `runtime\service.stderr.log` в поддержку;
- незавершённый RUN после restart нужно построить заново, поскольку RUN хранится в памяти процесса;
- сохранённые справочники и mappings после restart не теряются — они находятся в `runtime\local.db`.

Пароль Excel в журналы не записывается.

## 13. Граница безопасности

Версия предназначена только для локального preview и Excel-экспорта. ADO, ODBC, запись в 1С, изменение производственной базы и live write отсутствуют.
