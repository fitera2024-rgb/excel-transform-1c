## Текущий проект User Flow

1. Пользователь загружает/обновляет необходимые справочники либо использует уже загруженные утверждённые справочники.
2. Пользователь выбирает контекст из справочников: период сценария, сценарий, единицу отчёта, организацию пути 1С, вид отчёта и другие реально необходимые поля. Точные зависимости определить после анализа справочников.
3. Пользователь выбирает бюджетный Excel.
4. Сервис структурно находит подготовленный загрузочный диапазон; имя листа не является authority. Если найдено несколько подходящих вариантов, сервис не угадывает молча, а предлагает понятный выбор пользователя.
5. Сервис читает рассчитанные значения Excel, не требуя Paste Values и не воспроизводя Excel Calculation Engine.
6. Сервис валидирует данные и нормализует каждую исходную строку во все 12 месяцев, включая нули.
7. Сервис выполняет точное ERP-сопоставление по иерархии там, где match однозначен; неоднозначности не угадываются.
8. Неоднозначный или отсутствующий реквизит, контекстное значение, mapping либо отдельное target-поле не останавливают построение максимально возможного preview. Неразрешённое значение получает `Требует внимания`, а только минимально неформируемая единица — `Пропущено`.
9. Пользователь видит основной максимально полный preview, включая записи со статусом `Требует внимания`.
10. Пользователь видит Реестр ошибок/внимания с точными указателями на исходный Excel.
11. Пользователь может прямо в сервисе исправлять бизнес-реквизиты из загруженных справочников, выбирать неоднозначный контекст/источник и вручную выбирать ERP-код.
12. После правок preview обновляется без потери уже обработанного результата и без необходимости заново запускать весь процесс.
13. Пользователь получает/экспортирует нормализованный результат первой vertical slice.

## UX-принцип

`Preview = максимально полный результат`

`Реестр ошибок = проблемы + точные указатели`

`ADO-ready = отдельный будущий фильтр`

Пользовательские состояния: `ОК`, `Требует внимания`, `Пропущено`.

Для первой vertical slice действует принцип **continue with attention**, а не общий fail-closed: сервис не угадывает неоднозначные значения, но сохраняет и показывает всю полезную часть результата.

Полная остановка допускается только если технически невозможно получить какой-либо полезный результат: файл не открывается/повреждён либо не найден ни один распознаваемый загрузочный диапазон.

Неоднозначность будущего места записи в 1С может остановить только write-операцию; уже сформированные validation, transformation и preview не теряются.

## Не входит в первую vertical slice

- ADO live write;
- запись в TEST/PROD 1С;
- автоматический merge/release;
- прямой SQL-write во внутренние таблицы 1С;
- технические SHA/path/debug/proof controls в normal UI;
- реконструкция подготовленного загрузочного диапазона из расчётных департаментских листов.
