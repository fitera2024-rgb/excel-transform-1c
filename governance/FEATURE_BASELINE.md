# Feature Baseline

STATUS: `CANONICAL_PREVIEW_EXPORT_BASELINE_ACCEPTED / L_INTEGRATION / NO_RELEASE_APPROVAL / NO_LIVE_WRITE`

Каждый принятый функциональный инвариант получает стабильный ID. Потеря функции без явного разрешения = regression.

| ID | Area | Baseline |
|---|---|---|
| SCOPE-001 | Product | Продукт — локальный внутренний конвертер ограниченного набора бюджетных Excel-таблиц в согласованный формат для 1С, а не универсальная платформа или глобальный сервис |
| ENG-001 | Engineering | Архитектура, safety и governance должны быть минимально достаточными; новый контроль допускается только для конкретного реального риска при отсутствии более простого решения |
| ENG-002 | Engineering | Multi-tenant, enterprise RBAC, универсальные Rules/Plugin Engine, cryptographic proof UI, распределённая инфраструктура и тяжёлое release orchestration не входят в scope без отдельного owner decision |
| INPUT-001 | Excel | Пользователь может выбрать входной Excel |
| INPUT-002 | Excel | Источник определяется по структуре/schema, не по имени файла |
| INPUT-003 | Excel | V1 использует уже подготовленный загрузочный диапазон расходов и не реконструирует его из расчётных департаментских листов |
| INPUT-004 | Excel | Формулы в загрузочном диапазоне разрешены; сервис читает рассчитанные/сохранённые значения, Paste Values не требуется |
| INPUT-005 | Excel | При нескольких структурно подходящих диапазонах сервис предлагает пользовательский выбор и не угадывает источник молча |
| INPUT-006 | Excel | Фактический формат определяется по содержимому; original snapshot неизменяем, decrypt/legacy conversion/repair выполняется только в отдельной working copy |
| INPUT-007 | Excel | V1 структурно поддерживает годовой и одногомесячный Инталев ОПИУ наряду с подготовленными бюджетными диапазонами |
| INPUT-008 | Excel | Полный БДР определяется структурно и обрабатывается как один business source с KPI, доходами, расходами и доказанными prepared-компонентами |
| INPUT-009 | Excel | Для полного БДР saved-value sheet используется только по exact связи `лист + строка + показатель + месяц`; текст формулы не становится числовым значением |
| VAL-001 | Validation | Проблемы данных показываются пользователю понятным бизнес-языком |
| ERR-001 | Validation | Локальная ошибка не блокирует весь файл; пропускается только минимально необходимый результат |
| ERR-002 | Validation | Ошибка общего поля не исключает автоматически все 12 месяцев исходной строки |
| ERR-003 | Validation | Реестр ошибок/внимания содержит точный указатель на исходный Excel и максимум доступного бизнес-контекста |
| ERR-004 | Validation | Неоднозначный или отсутствующий реквизит, контекст, mapping либо отдельное target-поле не блокируют весь preview при наличии распознаваемого входа; сервис не угадывает значение, а отмечает `Требует внимания`/`Пропущено` и продолжает полезную обработку |
| ERR-005 | Validation | Полная остановка первой vertical slice разрешена только если файл технически непригоден либо не найден ни один распознаваемый загрузочный диапазон |
| ERR-006 | Validation | Ошибки за пределами официального загрузочного диапазона V1 не включаются в Реестр ошибок и не блокируют результат |
| TAX-001 | Validation | `?`, пустое и неоднозначный числовой `0` по налогообложению требуют внимания, но не блокируют весь preview |
| TAX-002 | Validation | Числовые `0.2` и `0.22` детерминированно нормализуются как `20%` и `22%`; числовой `0` не трактуется как `0%` без однозначного справочника |
| TAX-003 | Validation | Пользователь может явно установить `Налогообложение: не требуется`; решение не угадывает налоговый режим, снимает только tax-причину и применяется ко всем месяцам source row без rerun |
| TAX-004 | Validation | Массовое tax-действие требует отдельной явной галки, считает source rows, исключает уже решённые строки и является идемпотентным |
| AMOUNT-001 | Validation | Отрицательная сумма сохраняется без изменения знака, остаётся в preview/result и получает `Требует внимания` с комментарием `Отрицательная сумма` |
| CONTEXT-001 | Context | Контекст выбирается пользователем из загруженных утверждённых справочников, не угадывается по filename/path/случайной ячейке |
| CONTEXT-002 | Context | `Единица отчёта` и `Организация пути 1С` не объединяются без доказанного mapping |
| CONTEXT-003 | Context | `Сценарий` и `Период сценария` являются отдельными полями |
| CONTEXT-004 | Context | Если Excel не позволяет подтвердить выбранный реквизит, authority остаётся пользовательский выбор; явное противоречие показывается как понятная проблема |
| REPORT-001 | Context | Вид отчёта V1 зафиксирован как `Отчет о прибылях и убытках`, код `ОтчетОПрибыляхИУбытках`; отдельная запись `ОПИУ` не предлагается как альтернативный вид отчёта V1 |
| SCENARIO-001 | Context | `ПЛАН_2026` и `ПЛАН 2026` считаются одним сценарием; каноническое имя `ПЛАН 2026`, год `2026` |
| SCENARIO-002 | Context | ERP-код сценария является дополнительным атрибутом; основной persisted identity — стабильный локальный идентификатор |
| SCENARIO-003 | Context | Пользователь может добавить новый сценарий; он постоянно сохраняется локально и виден всем пользователям локального сервиса |
| SCENARIO-004 | Context | Новый сценарий без ERP-подтверждения разрешён для validation/preview/export и помечается `Не подтверждён справочником ERP`; будущий write запрещён до подтверждения |
| PERIOD-001 | Context | Интерфейс содержит явную галочку `Весь год`, включённую по умолчанию; после её снятия можно выбрать один или несколько месяцев, а отсутствие любого выбора даёт понятную validation-ошибку |
| PERIOD-002 | Context | Внутренняя identity месячной записи — год и номер месяца; трансформация формирует все 12 месяцев независимо от экранного фильтра |
| ORG-001 | References | Организации, промежуточные узлы, подразделения и ЦФО образуют одно вложенное дерево `Организации`, а не независимые справочники |
| ORG-002 | References | Организационный выбор иерархический: сначала верхняя ветка, затем сам верхний либо любой дочерний узел её поддерева |
| ORG-003 | References | Для `ПС` нет заранее установленного mapping; пользователь выбирает организационный узел/ветку вручную при каждом запуске |
| ORG-004 | References | Все узлы показываются без автоматического фильтра по недоказанным полям статуса/типа; код и полный путь доступны пользователю |
| CFO-001 | References | Классификатор ЦФО Инталев определяется структурно, сохраняется локально и дополняется по exact source key |
| REF-005 | References | Чистый пакет содержит базовые ERP/organization/scenario/Intalev-CFO каталоги; пользовательские импорты дополняют baseline и обновляют только exact stable key |
| CFO-002 | Mapping | Exact source CFO сопоставляется только с явно выбранным конкретным узлом дерева 1С; выбор организации RUN и CFO mapping не смешиваются |
| CFO-003 | Mapping | Fuzzy/typo/case/name-only automatic CFO mapping запрещён; одинаковые display names не объединяются молча |
| CFO-004 | Mapping | Подтверждённый CFO mapping применяется ко всем строкам/месяцам source CFO, сохраняется после restart и не требует полного rerun |
| CFO-005 | Mapping | Массовое CFO-действие считает уникальные source CFO, требует явной галки, валидирует весь набор до записи и не делает partial update |
| REF-001 | References | Названия `!!!Удалить`/`Удалить` не являются основанием для автоматического скрытия или исключения записи |
| ACCESS-001 | Access | `REMOVED_AUTHORIZED`: V1 не ограничивает дерево организаций по пользователям; всем доступно всё локально загруженное дерево |
| ACCESS-002 | Access | `REMOVED_AUTHORIZED`: объединение делегированных поддеревьев не применяется, потому что делегирование удалено из V1 |
| ACCESS-003 | Access | `REMOVED_AUTHORIZED`: экранные списки не фильтруются по effective access; отдельного access-контекста нет |
| ACCESS-004 | Access | `REMOVED_AUTHORIZED`: экран и бизнес-действие делегирования удалены по явному owner decision во время UX Smoke |
| MAP-001 | ERP mapping | ERP-код выбирается автоматически только при точном однозначном match по принятой иерархии/атрибутам |
| MAP-002 | ERP mapping | При неоднозначности пользователь выбирает ERP-код вручную; autonomous fuzzy/typo/case auto-match запрещён |
| MAP-003 | ERP mapping | Подтверждённый mapping можно повторно применять только в доказанно том же контексте; одно название статьи не является reusable global key |
| MAP-004 | ERP mapping | Конфликт иерархии не разрешается самостоятельным игнорированием hierarchy; требуется явный пользовательский выбор |
| MAP-005 | ERP mapping | Базовый reusable key ручного mapping: вид отчёта + полный путь `тип расходов → группа расходов → исходная статья`; организация/департамент/ЦФО в него не входят |
| OPIU-RULE-001 | Indicator | Для расходов indicator authority: exact `группа раскрытия → статья → supported formula/source predicates → показатель` |
| OPIU-RULE-002 | Indicator | При наличии formula/source catalog конфликтующий legacy classifier не перекрывает его; legacy разрешён только как exact `группа → статья` fallback при отсутствии authority |
| OPIU-RULE-003 | Indicator | Deepest exact disclosure group имеет приоритет; ERP-code conflict не игнорируется |
| OPIU-RULE-004 | Indicator | Unsupported/missing/ambiguous condition fail closed только для indicator resolution: row-level preview сохраняется, `Показатели` не заполняется догадкой |
| OPIU-RULE-005 | Indicator | KPI полного БДР сохраняет exact source indicator; доходы и количества используют принятые exact structural resolvers |
| OPIU-RULE-006 | Indicator | Global article-name-only, fuzzy, contains, typo/case correction и first-candidate selection запрещены; `core/opiu_rules` не является universal Rules Engine |
| TRANS-001 | Core | Трансформация отделена от UI и ADO |
